# 播放链路说明

本文档说明当前项目中统一后的播放链路。

> 2026-05 更新：播放器已从“页面调用公共工具后直接切状态”升级为 `playerStore` 内部统一播放资源事务。`song / podcast / cloud / local` 都必须通过同一条事务链路切换音频、当前曲目、歌词和迷你窗口快照。

## 1. 目标

播放链路统一的目标是：

- 首页、云盘、歌单详情页都使用同一种播放方式
- 不在首屏批量请求所有播放地址
- 只有在真正播放时才获取单曲 URL
- 切歌时真实 `audio.src`、封面、歌词、播放队列、迷你窗口状态保持一致
- 支持本地歌曲、在线歌曲、云盘歌曲、播客混合队列

---

## 2. 当前核心链路

文件：`src/stores/player.ts`

### 播放资源身份

播放器使用 `getTrackPlaybackKey(track)` 区分不同资源，避免本地歌曲、在线歌曲、播客节目 ID 碰撞：

- 本地歌曲：`local:${id}:${path}`
- 播客节目：`podcast:${id}:${programId || rid}`
- 云盘歌曲：`cloud:${id}:${cloudSid}`
- 在线歌曲：`song:${id}`

该 key 只用于播放事务、歌词刷新、桌面歌词和迷你歌词同步；收藏、评论、喜欢状态仍按原业务 ID 处理。

### 统一播放资源事务

`playByIndex(index)` 不再提前提交 `currentTrack`。当前流程是：

1. 从 `playlist[index]` 取目标资源
2. 调用 `playTrack(target, { index, reason: 'switch-track' })`
3. `playTrack()` 解析本地文件或远程 URL
4. 统一执行 `pause -> src -> load -> play`
5. `audio.play()` 成功后才提交 `currentTrack/currentIndex/currentSongId`
6. 同步 runtime snapshot、迷你窗口、桌面歌词和持久化

这样可以避免“封面已经切到下一首，但音频仍在播放上一首”的半提交状态。

### 音质切换兼容

旧签名仍保留：

- `playTrack(track)`
- `playTrack(track, seekTo)`

当传入当前播放资源并带 `seekTo` 时，播放器把它视为 `reload-source`，只重新解析音源并保持当前进度，不重置队列和歌词。

音质切换成功后，底部控制栏 toast 使用 `currentQualityLabel` 提示实际交付音质；如果请求音质不可用但向下回退成功，则提示“已自动切换为实际音质”。如果换源失败，`switchAudioSource()` 会恢复旧 `audio.src`、旧进度、`crossOrigin` 和播放状态，避免半提交。

### 统一音频切源

本地歌曲、在线歌曲、云盘歌曲、播客最终都会进入统一切源函数：

```text
pause()
  -> 设置 audio.src
  -> audio.load()
  -> 必要时恢复 currentTime
  -> resume AudioContext
  -> audio.play()
  -> commit 当前播放资源
```

本地歌曲使用 `localApi.readFile(path)` 创建 blob URL；旧 blob URL 在新源确认设置后释放。远程资源通过 `resolvePlayUrl()` 解析播放 URL，并保持 EQ 开启时所需的 `crossOrigin = 'anonymous'`。

当 EQ 开启且目标是远程 HTTP(S) 音频时，播放器会先把 URL 包装为 `/dl-proxy?url=...`，再设置到 `<audio>`。这样可以避免官方或第三方 CDN 缺少 CORS 响应头导致 `audio.play()` 失败。

### 播客特殊规则

- 播客也走远程资源事务，不单独创建播放器。
- 付费播客在事务提交前拦截，不会把付费节目提交为当前播放。
- `paidContentSkip = true` 时从目标 index 后继续找下一条可播放资源。
- 播客不走普通歌曲 `getSongDetail()` 回写，避免污染 `description / podcast.programId / rid`。

## 3. 首页播放链路

### 每日推荐

首页每日推荐卡片点击歌曲时：

1. 从 `dailyRecommendSongs` 中取对应歌曲
2. 调用 `playerStore.setPlaylist(...)`
3. 调用 `playerStore.playByIndex(index)`
4. 由 `playerStore.playTrack()` 在真正播放时按需解析 URL

### 结果

- 不再在首页预先请求所有播放地址
- 首页更快

---

## 4. 歌单详情页播放链路

### `PlaylistDetailPage.vue`

#### 播放单曲
- 点击单曲时设置 playlist，并调用 `playByIndex(index)`

#### 播放全部
- 实际上播放列表第一首
- 播放器事务按需拿第一首 URL
- `audio.play()` 成功后才提交当前曲目

### 结果

- 统一和首页、云盘一致
- 不再依赖首屏全量 URL

---

## 5. 云盘播放链路

### 过去
云盘会在加载阶段给每首歌批量请求 `getSongUrl()`，导致首屏慢。

### 现在
云盘改成：

- 首屏只加载歌曲元信息
- 真正播放时再按需取 URL

### 结果

- 云盘详情页更快
- 播放逻辑和其他页面一致

---

## 6. 播放策略总结

### 首屏策略
- 只显示列表和封面
- 不批量请求 URL

### 播放时策略
- 需要播放哪首，就解析哪首 URL
- 交给 `playerStore` 统一播放事务处理

### 下一首播放

页面不应直接 `playerStore.state.playlist.splice()`。

统一使用：

```ts
playerStore.insertNext(track)
```

它会负责：

- 规范化 track
- 插入到当前播放项之后
- 同步 runtime snapshot
- 持久化播放队列

当前已接入歌单、专辑、歌手详情页和本地音乐相关入口。

---

## 7. 当前统一后的体验

- 每日推荐播放
- 云盘播放
- 普通歌单播放

都走同一条逻辑：

1. 获取歌曲对象
2. 设置播放列表
3. 调用 `playByIndex`
4. 按资源类型解析 URL 或本地 blob
5. 切换真实 audio source
6. 成功后提交当前播放状态

---

## 8. 验证路径

本次统一事务修复后，以下路径必须作为回归验证：

1. 本地歌曲播放 -> 每日推荐添加下一首 -> 播放页点击下一首
2. 本地歌曲播放 -> 播客入队 -> 下一首
3. 在线歌曲 -> 本地歌曲 -> 在线歌曲
4. 播客 -> 在线歌曲
5. 在线歌曲 -> 播客
6. 音质切换保持当前进度
7. EQ 开启后切歌仍可播放
8. 付费播客提示和跳过逻辑保持
9. 迷你窗口下一首与主窗口播放队列一致
10. 清空播放列表后迷你歌词不残留

---

## 9. 结论

现在播放链路已经从“按页面分别实现”统一成了“播放器 store 内部事务统一处理”。

这带来的主要收益是：

- 更少重复代码
- 更快首屏
- 更一致的播放体验
- 更容易扩展新的歌单样式入口
- 避免 UI 状态和真实音频源不同步
- 支持本地、在线、云盘、播客混合队列
