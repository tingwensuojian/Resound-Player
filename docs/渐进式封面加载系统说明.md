# 渐进式封面加载系统说明

本文档记录项目中为实现"消除半张半张加载、优化多设备封面体验"而实现的渐进式封面加载系统，包括三层渐进管道、设备自适应降级、Service Worker 缓存及组件接入清单。

---

## 1. 问题背景

项目中封面图片以两种方式加载：

| 方式 | 表现 | 覆盖范围 |
|------|------|----------|
| `<img>` 标签 + `loading="lazy"` | 浏览器原生 JPEG 渐进式渲染可见，出现"上半张→下半张→清晰" | 95% 的列表卡片、搜索结果、详情页列表 |
| CSS `background-image` + `useBgLoaded` | 预加载后以 0.25s 淡入，消除渐进渲染 | 仅 5 处（首页 3 卡片 + PlayerBar + PlayerExpanded） |

两种方式共同的问题是：
- **无设备差异**：低端设备和高端设备加载相同尺寸封面，低端设备带宽/内存浪费
- **无多级降级**：图片加载失败时无中间态兜底，直接显示白/灰块
- **无缓存层**：二次访问仍需网络请求封面
- **双重加载**：`GradientCard::before` 独立加载 `background-image`，与 `<img>` 形成两次 HTTP 请求

## 3. 核心 Composable: `useProgressiveCover`

**文件**：`src/composables/useProgressiveCover.ts`

### 3.1 三层 URL 生成

利用网易云 API 原生 `?param=NxN` 参数实现多级分辨率：

| 层级 | 尺寸参数 | 典型大小 | 用途 |
|------|----------|----------|------|
| LQIP | `100y100` | ~3-5 KB | 立即显示的模糊占位 |
| thumb | `300y300` | ~15-30 KB | 快速加载后替换 LQIP |
| medium | `640y640` | ~50-80 KB | 中等画质（中端设备终态） |
| large | `1024y1024` | ~100-200 KB | 全尺寸（高端设备终态） |

```ts
// URL 变换示例
// 原始:  https://p2.music.126.net/xxx/yyy.jpg
// LQIP:  https://p2.music.126.net/xxx/yyy.jpg?param=100y100
// thumb: https://p2.music.126.net/xxx/yyy.jpg?param=300y300
// large: https://p2.music.126.net/xxx/yyy.jpg?param=1024y1024
```

### 3.2 设备自适应降级

```ts
function getDeviceTier(): 'low' | 'mid' | 'high'
```

| 等级 | 判定条件 | 最终加载尺寸 | 渐入动画 |
|------|----------|-------------|---------|
| low | RAM<4GB / CPU≤4核 / 2G/慢速网络 | 仅 thumb (300px) | 跳过（`transition: none`） |
| mid | RAM<8GB / CPU≤8核 | medium (640px) | 320ms |
| high | 其余（含桌面端） | large (1024px) 或自定义 | 380ms |

判定使用 `navigator.deviceMemory`、`navigator.hardwareConcurrency`、`navigator.connection.effectiveType` 和 `saveData`。所有 API 不可用时安全回退，不误判。

### 3.3 返回值

```ts
const {
  lqipUrl,       // Ref<string>   — 100px 占位 URL
  thumbUrl,      // Ref<string>   — 300px 缩略图 URL
  targetUrl,     // Ref<string>   — 目标尺寸 URL
  lqipLoaded,    // Ref<boolean>  — LQIP 加载完成
  thumbLoaded,   // Ref<boolean>  — 缩略图加载完成
  targetLoaded,  // Ref<boolean>  — 目标尺寸加载完成
  showFinal,     // Ref<boolean>  — 最终层可显示（不同设备触发时机不同）
  deviceTier,    // 'low'|'mid'|'high'
  skipAnimation, // boolean       — 低端设备 true
  loadedClasses, // Computed      — CSS 类名对象（供 :class 绑定）
  srcset,        // Computed      — 响应式图片 srcset 字符串
} = useProgressiveCover(() => props.cover, { targetSize: 'large' })
```

### 3.4 三层预加载时序

```
时间轴 →
├──── 0ms ────├──── 50~200ms ────├──── 300ms~1.5s ────┤
│             │                  │                    │
│ LQIP 请求   │ LQIP 完成        │ thumb 完成         │ full 完成
│ (100px)     │ → LQIP 层显示    │ → thumb 层显示     │ → full 层显示
│             │                   │ → LQIP 层淡出     │ → thumb 层淡出
```

## 4. CSS 叠层方案

**文件**：`src/styles/animations.css`

### 4.1 三层叠层

使用 CSS Grid 单格叠层而非 `position: absolute`，关键在于 `<img>` 保持流内布局以提供内容高度：

```css
.progressive-cover {
  display: grid;
  width: 100%;
  overflow: hidden;
  background: var(--bg-surface, #1c1917);
}
.progressive-cover > * {
  grid-area: 1 / 1;       /* 所有子元素叠在同一格 */
  width: 100%;
  height: 100%;
  overflow: hidden;
}
```

**为什么不用 `position: absolute`**：`position: absolute` 将子元素移出流内，当父容器没有显式高度时（如 CSS Grid 单元格未设 `grid-auto-rows`），容器高度坍缩为 0，封面不可见。CSS Grid 叠层让 `<img>` 标签的自然尺寸撑开容器。

### 4.2 层过渡

| 选择器 | 作用 |
|--------|------|
| `.progressive-cover__lqip` | 初始 `opacity: 1`，thumb 加载后 `opacity: 0` |
| `.progressive-cover__thumb.loaded` | `opacity: 0 → 1`，`~ .lqip` 同步淡出 LQIP |
| `.progressive-cover__full.loaded` | `opacity: 0 → 1`，`~ .thumb` 同步淡出 thumb |
| `.progressive--skip-animation` | 低端设备 `transition: none !important` |

### 4.3 可访问性

```css
/* prefers-reduced-motion → 禁用所有过渡 */
@media (prefers-reduced-motion: reduce) { ... }
/* prefers-reduced-data → 只显示 LQIP，不加载缩略图和全尺寸 */
@media (prefers-reduced-data: reduce) { ... }
```

## 5. Service Worker 缓存

### 5.1 文件结构

| 文件 | 类型 | 用途 |
|------|------|------|
| `public/sw.js` | Service Worker | 拦截封面请求，cache-first 策略 |
| `src/utils/swRegister.ts` | 注册工具 | 环境检测 + 注册 + 预缓存 API |

### 5.2 缓存策略

```
用户请求封面
      │
      ▼
  拦截 music.126.net 图片
      │
   cache.match() 命中? ──YES──→ 返回缓存
      │ NO
      ▼
  网络请求 → 返回响应 → 异步写入 CacheStorage
                              │
                          LRU 淘汰: >500条删最早50条
```

实现注意：

- `fetch` handler 返回给页面的 `Response` 与写入 CacheStorage 的 `Response` 必须分离。
- 写缓存前要先执行 `response.clone()`，再把 clone 交给 `writeToCache()`。
- 不要在 `writeToCache()` 内对已被页面消费的响应再次 `clone()`，否则会触发 `Failed to execute 'clone' on 'Response': Response body is already used`。

### 5.3 环境兼容

| 环境 | SW 支持 | 行为 |
|------|---------|------|
| Web 开发 (localhost:5173) | ✅ | 注册，缓存封面 |
| Web 生产 (HTTPS) | ✅ | 注册，缓存封面 |
| Electron 桌面 (file://) | ❌ 跳过 | 无 SW，fallback 到浏览器 HTTP 缓存 |
| Web HTTP (非 localhost) | ❌ 跳过 | 浏览器限制，静默跳过 |

### 5.4 预缓存队列

通过 `postMessage` 驱动：

```ts
import { preloadCovers } from '../utils/swRegister'

// 将可见区域内的封面 URL 加入预缓存队列
// SW 在空闲时逐批取 3 张处理
preloadCovers(['https://p2.music.126.net/...?param=300y300', ...])
```

## 7. 与旧系统 `useBgLoaded` 的关系

| 维度 | `useBgLoaded` | `useProgressiveCover` |
|------|---------------|----------------------|
| 加载层级 | 单层（完整图） | 三层（LQIP→thumb→full） |
| 设备适配 | 无 | low/mid/high 三级降级 |
| 加载源 | 原 URL | 利用 `?param=NxN` 多级尺寸 |
| 显示方式 | CSS `background-image` | CSS Grid `<img>` 叠层 |
| 可访问性 | 无 | `prefers-reduced-motion/data` |
| 使用场景 | background-image 元素 | 有明确尺寸容器的封面 |

**并行使用**：两个 composable 互不冲突，可共存。`useBgLoaded` 仍用于背景图片（如首页卡片底图），`useProgressiveCover` 用于可展示多层 `<img>` 的封面组件。

## 8. 开发与移植指南

### 8.1 为新组件接入三层渐进

```ts
// 1. 引入 composable
import { useProgressiveCover } from '../composables/useProgressiveCover'

// 2. 传入响应式 URL getter
const {
  lqipUrl, thumbUrl, targetUrl,
  thumbLoaded, targetLoaded,
  loadedClasses, srcset,
} = useProgressiveCover(() => props.cover, { targetSize: 'large' })
```

```html
<!-- 3. 模板：使用 .progressive-cover 容器 -->
<div class="progressive-cover" :class="loadedClasses">
  <!-- LQIP 模糊占位 -->
  <span class="progressive-cover__lqip"
        :style="{ backgroundImage: `url(${lqipUrl})` }"></span>
  <!-- 缩略图 -->
  <img class="progressive-cover__thumb"
       :class="{ loaded: thumbLoaded }"
       :src="thumbUrl" alt="" decoding="async" />
  <!-- 全尺寸图 -->
  <img class="progressive-cover__full cover"
       :class="{ loaded: targetLoaded }"
       :src="targetUrl" :srcset="srcset"
       sizes="..." alt="" decoding="async" />
</div>
```

```css
/* 4. 确保父容器有明确尺寸（aspect-ratio / 百分比高度 / 固定高度） */
.media-container { aspect-ratio: 1; } /* 或 width: 200px; height: 200px; */
```

### 8.2 注意事项

- `.progressive-cover` 容器**必须有明确尺寸**（来自父容器或自身 `aspect-ratio`），否则 `grid-area: 1/1` 的子元素无空间渲染
- 如果容器尺寸来自子 `<img>` 的自然尺寸（如 CSS Grid 项目没有固定行高），可以依赖 `<img>` 标签的加载后自然宽高撑开容器
- 如果父容器没有显式尺寸且不能依赖 `<img>` 撑开（如 flex/grid 子项），应回退到单层 `<img>` 方式
