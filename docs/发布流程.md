# 发布流程

> 更新版本号、推送 Git 并发布 GitHub Release 的标准操作流程。

---

## 前置条件

- 本地所有改动已完成开发并自测通过
- 当前工作区干净（无未保存的修改）
- 拥有 GitHub 仓库的推送权限

---

## 步骤

### 1. 更新版本号

需要同时修改以下文件中的版本号：

**package.json**
```json
```

**electron/package.json**
```json
{"version":"X.X.X"}
```

**README.md**（两处位置）
- 顶部简介中的版本标识：`当前仓库已经完成 vX.X.X 发布`
- 基本信息中的版本：`- 当前版本：X.X.X`


### 2. 收集已推送的 commit 信息

在整理 Release Notes 之前，先用 git 查看自上次发布 tag 以来所有已推送但未发布的 commit：

`ash
# 查看自上个 tag（如 v1.2.0）以来的所有 commit
git log v1.2.0..HEAD --oneline --no-decorate

# 查看详细的变更内容
git log v1.2.0..HEAD --stat
`

> 注意：如果中间有多个已推送的 commit，它们也必须纳入 Release Notes，**不得遗漏**。
> 例如同时存在「修复 A」「修复 B」「修复 C」三个 commit，Release Notes 要逐一覆盖。

### 3. 整理更新摘要

将本次发布的变更（已推送 commit + 本地新增改动）整理为 Release Notes，按以下格式分类：

```
### 修复
- 条目

### 功能
- 条目

### CI
- 条目
```

### 4. 提交并打标签

```bash
cd work
git add electron/main.js electron/package.json package.json src/App.vue
git commit -m "vX.X.X"
git tag vX.X.X
git push origin main
git push origin vX.X.X
```

> 推送 tag 后 GitHub Actions 会自动触发各平台构建。

### 5. 创建 GitHub Release

> 禁止使用 `curl -d @file` 或 `curl -d '...'` 直接发送含中文的 JSON 负载。PowerShell 下管道传递中文会导致编码有损，中文变成 `?`。
> 推荐使用 Python 脚本通过 `urllib.request` 发送请求，避免编码问题。

#### 5.1 生成 Release body JSON 文件

将以下脚本保存为 `scripts/create-release.py`（替换版本号和更新摘要）：

```python
import json

body = """## vX.X.X 更新内容

### 修复
- 条目

---

## 下载说明

### Windows

| 文件 | 适用场景 | 说明 |
|---|----|---|
| Resound-Player Setup X.X.X.exe | **日常使用（推荐）** | NSIS 安装包 |
| Resound-Player-X.X.X.exe | **U 盘携带、临时使用** | 便携版 |

### macOS

| 文件 | 适用场景 | 说明 |
|---|----|---|
| Resound-Player-Mac-x64-X.X.X.dmg | **Intel 芯片** | DMG 安装包 |
| Resound-Player-Mac-arm64-X.X.X.dmg | **Apple 芯片** | DMG 安装包 |
"""

payload = {
    "tag_name": "vX.X.X",
    "name": "Resound-Player vX.X.X",
    "body": body,
    "draft": False,
    "prerelease": False,
}

with open("release_payload.json", "w", encoding="utf-8") as f:
    json.dump(payload, f, ensure_ascii=False)

print("Payload written to release_payload.json")
```

> 表格分隔行必须使用纯管道符 `|`（ASCII 0x7C），禁止使用 `\u009c` 等控制字符。格式参考 ` |---|----|---| `

#### 5.2 获取 GitHub Token

打开 PowerShell，执行以下命令读取 Git 凭据中存储的 Token：

```powershell
$cred = "protocol=https`nhost=github.com`n" | git credential fill 2>$null
$token = ($cred -split "`n" | Where-Object {$_ -like "password=*"} | ForEach-Object {$_.Substring(9)}).Trim()
```

#### 5.3 发送 API 请求创建 Release

```powershell
python -c "
import urllib.request, json

tag = 'vX.X.X'
token = '$token'

with open('release_payload.json', 'r', encoding='utf-8') as f:
    payload = f.read()

req = urllib.request.Request(
    f'https://api.github.com/repos/tingwensuojian/Resound-Player/releases',
    data=payload.encode('utf-8'),
    headers={
        'Authorization': f'Bearer {token}',
        'Accept': 'application/vnd.github+json',
        'Content-Type': 'application/json; charset=utf-8',
    },
    method='POST'
)
resp = urllib.request.urlopen(req)
result = json.loads(resp.read().decode('utf-8'))
print('Release created:', result.get('html_url'))
"
```

#### 5.4 验证 Release body

```powershell
python -c "
import urllib.request, json

req = urllib.request.Request(
    f'https://api.github.com/repos/tingwensuojian/Resound-Player/releases/tags/vX.X.X',
    headers={'Accept': 'application/vnd.github+json'}
)
resp = urllib.request.urlopen(req)
result = json.loads(resp.read().decode('utf-8'))
body = result['body']

if any(ord(c) > 0x4e00 for c in body):
    print('OK: Chinese characters intact')
else:
    print('ERROR: Chinese characters lost, encoding corrupted')

if '|---|' in body:
    print('OK: Table separators correct')
else:
    print('ERROR: Table separators may be wrong')

print()
print('Release body preview:')
print(body[:300])
"
```

> 若验证未通过，使用 PATCH 更新（`method='PATCH'`，URL 追加 release ID）。
### 6. 等待 CI 构建完成

推送 tag 后，GitHub Actions 会自动执行：

| 工作流 | 产物 |
|--------|------|
| Build Windows App | NSIS 安装包 + 便携版 |
| Build macOS App | DMG (x64 + arm64) |

可在 [Actions 页面](https://github.com/tingwensuojian/Resound-Player/actions) 查看进度。

构建完成后，产物会自动上传到 Release 页面。

---

## 校验清单

Release 发布后，必须验证以下三项：

1. **Release 页面打开正常** — 无 404，版本号正确
2. **更新摘要中表格正确渲染** — 表格分隔行使用 `纯管道符 | + 短横 -`，格式参考 ` |---|----|---| `
3. **中文内容未变成 `?`** — Release body 中的中文必须完整显示

> 若发现中文变成 `?`，说明 API 请求时的编码有损，改用 Python 脚本发送请求（见第 4 步中的推荐方案）。

## 注意事项

### UTF-8 BOM

PowerShell 的 Set-Content / Out-File 默认会给文件添加 UTF-8 BOM，这会导致 vite.config.ts 中 JSON.parse 读取 package.json 失败。

解决方法：使用 .NET 的 [System.IO.File]::WriteAllBytes() 写入不含 BOM 的 UTF-8，或使用 `git show HEAD:file > file` 恢复。

修改 package.json 后务必验证：
```bash
node -e "console.log(JSON.parse(require('fs').readFileSync('./package.json','utf8')).version)"
```

### Release 名称格式

所有 Release 名称统一为 `Resound-Player vX.X.X`。

CI 工作流中 gh release create/edit 的 --title 参数必须与此格式一致：
- .github/workflows/build-win.yml：`--title "Resound-Player v$Version"`
- .github/workflows/build-mac.yml：`--title "Resound-Player ${TAG}"`

### CI 覆盖 Release 标题

GitHub Actions 构建完成后会通过 gh release edit 更新 Release 标题和说明。如果手动创建 Release 时的标题格式与 CI 不一致，会被 CI 覆盖。确保 CI 配置中的标题格式与手动创建时一致。

### Release 说明的中文乱码

PowerShell 的 ConvertTo-Json 会导致 Unicode 字符编码问题。发送 API 请求时使用原始 JSON 字符串拼接（ConvertTo-Json 仅处理内层字符串）可避免乱码。
