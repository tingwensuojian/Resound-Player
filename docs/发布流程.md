# 发布流程

> 更新版本号、推送 Git 并发布 GitHub Release 的标准操作流程。

---

## 前置条件

- 本地所有改动已完成开发并自测通过
- 当前工作区干净（无未保存的修改）
- 拥有 GitHub 仓库的推送权限

---

## 步骤

### 1. 更新版本号

需要同时修改以下文件中的版本号：

**package.json**
```json
```

**electron/package.json**
```json
{"version":"X.X.X"}
```

**README.md**（两处位置）
- 顶部简介中的版本标识：`当前仓库已经完成 vX.X.X 发布`
- 基本信息中的版本：`- 当前版本：X.X.X`


### 2. 整理更新摘要

将本次发布的变更整理为 Release Notes，按以下格式分类：

```
### 修复
- 条目

### 功能
- 条目

### CI
- 条目
```

### 3. 提交并打标签

```bash
cd work
git add electron/main.js electron/package.json package.json src/App.vue
git commit -m "vX.X.X"
git tag vX.X.X
git push origin main
git push origin vX.X.X
```

> 推送 tag 后 GitHub Actions 会自动触发各平台构建。

### 4. 创建 GitHub Release

```bash
# 获取 GitHub Token（存储在 Windows 凭据管理器中）
# 通过 git credential 读取
echo "protocol=https
host=github.com
" | git credential fill

# 使用 API 创建 Release
TOKEN="ghp_xxxxxxxxxxxx"

curl -X POST https://api.github.com/repos/tingwensuojian/Resound-Player/releases \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{
  "tag_name": "vX.X.X",
  "name": "Resound-Player vX.X.X",
  "body": "## vX.X.X 更新内容\n\n### 修复\n- 条目\n\n---\n\n## 下载说明\n\n### Windows\n\n| 文件 | 适用场景 | 说明 |\n|------|---------|------|\n| Resound-Player Setup X.X.X.exe | **日常使用（推荐）** | NSIS 安装包 |\n| Resound-Player-X.X.X.exe | **U 盘携带、临时使用** | 便携版 |\n\n### macOS\n\n| 文件 | 适用场景 | 说明 |\n|------|---------|------|\n| Resound-Player-Mac-x64-X.X.X.dmg | **Intel 芯片** | DMG 安装包 |\n| Resound-Player-Mac-arm64-X.X.X.dmg | **Apple 芯片** | DMG 安装包 |",
  "draft": false,
  "prerelease": false
}'
```

### 5. 等待 CI 构建完成

推送 tag 后，GitHub Actions 会自动执行：

| 工作流 | 产物 |
|--------|------|
| Build Windows App | NSIS 安装包 + 便携版 |
| Build macOS App | DMG (x64 + arm64) |

可在 [Actions 页面](https://github.com/tingwensuojian/Resound-Player/actions) 查看进度。

构建完成后，产物会自动上传到 Release 页面。

## 注意事项

### UTF-8 BOM

PowerShell 的 Set-Content / Out-File 默认会给文件添加 UTF-8 BOM，这会导致 vite.config.ts 中 JSON.parse 读取 package.json 失败。

解决方法：使用 .NET 的 [System.IO.File]::WriteAllBytes() 写入不含 BOM 的 UTF-8，或使用 `git show HEAD:file > file` 恢复。

修改 package.json 后务必验证：
```bash
node -e "console.log(JSON.parse(require('fs').readFileSync('./package.json','utf8')).version)"
```

### Release 名称格式

所有 Release 名称统一为 `Resound-Player vX.X.X`。

CI 工作流中 gh release create/edit 的 --title 参数必须与此格式一致：
- .github/workflows/build-win.yml：`--title "Resound-Player v$Version"`
- .github/workflows/build-mac.yml：`--title "Resound-Player ${TAG}"`

### CI 覆盖 Release 标题

GitHub Actions 构建完成后会通过 gh release edit 更新 Release 标题和说明。如果手动创建 Release 时的标题格式与 CI 不一致，会被 CI 覆盖。确保 CI 配置中的标题格式与手动创建时一致。

### Release 说明的中文乱码

PowerShell 的 ConvertTo-Json 会导致 Unicode 字符编码问题。发送 API 请求时使用原始 JSON 字符串拼接（ConvertTo-Json 仅处理内层字符串）可避免乱码。
