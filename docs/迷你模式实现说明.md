# 迷你模式实现说明

## 概述

迷你模式将播放器收缩为桌面悬浮小窗。紧凑态为 `340×70`，打开播放列表时扩展为 `340×360`，仅显示播放控制、进度条和播放队列。**复用同一 BrowserWindow**，通过 IPC 缩放窗口 + 渲染层 `v-if` 分支切换布局，无需跨窗口状态同步。

## 架构全景

```
┌─────────────────────────────────────────────────────────┐
│  TopBar.vue                                              │
│  [PiP 图标按钮] ──click──→ uiStore.enterMiniMode()      │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
              preload.js 暴露的 appEnv.miniMode.enter()
                       │
                       ▼
              main.js IPC handler
              ├─ 保存窗口状态 → preMiniState
              ├─ setSize(340, 70) + 右上角定位
              ├─ setAlwaysOnTop(参数)
              ├─ [macOS] setWindowButtonVisibility(false)   ← 隐藏红绿灯
              └─ webContents.send('mini-mode:state-change', true)
                       │
                       ▼
              preload.js 监听 IPC
              └─ document.dispatchEvent(new CustomEvent('mini-mode-state', ...))
                       │
                       ▼
              App.vue document.addEventListener
              └─ uiStore.state.isMiniMode = true
                       │
                       ▼
              App.vue 模板 v-if 分支
              └─ <MiniPlayBar v-if="uiStore.state.isMiniMode" />
```

## 逐层详解

### 1. 主进程 — electron/main.js

#### 预存状态变量

```js
let preMiniState = null;  // 进入迷你时保存，退出时恢复
```

#### mini-mode:enter (L458–487)

```
流程:
1. 保存当前窗口的 { x, y, width, height, isMaximized, wasFullScreen }
2. 若全屏 → 先退出全屏，监听 leave-full-screen 后执行 applyMiniSize
3. 否则直接 applyMiniSize

applyMiniSize():
  - setResizable(false)           // 禁止手动拖拽缩放
  - setMinimumSize(340, 70)
  - setMaximumSize(340, 500)      // 高度上限 500（为播放列表下拉留空间）
  - setSize(340, 70)              // 默认紧凑高度
  - setPosition(右上角, 距边缘 20px)
  - setAlwaysOnTop(参数)
  - [macOS] setWindowButtonVisibility(false)   // 隐藏原生红绿灯按钮
  - webContents.send('mini-mode:state-change', true)
```

#### mini-mode:exit (L489–504)

```
流程:
1. setAlwaysOnTop(false)          // 强制取消置顶
2. setResizable(true)             // 恢复可缩放
3. setMinimumSize(1100, 700)      // 恢复最小尺寸
4. setMaximumSize(0, 0)           // 解除最大限制
5. 从 preMiniState 恢复 { width, height, x, y }
6. 若之前全屏 → setFullScreen(true)；若最大化 → maximize()
7. preMiniState = null
8. [macOS] setWindowButtonVisibility(true)   // 恢复原生红绿灯按钮
9. webContents.send('mini-mode:state-change', false)
```

#### mini-mode:set-always-on-top (L506–509)

仅在 `preMiniState` 存在时（即迷你模式激活中）调用 `win.setAlwaysOnTop(enabled)`。

#### mini-mode:resize (L511–515)

动态调整窗口高度，钳制范围 `70~500`，宽度固定 `340`。

当前用途：`MiniPlayBar` 打开播放列表时调用 `resize(360)`，关闭播放列表或组件卸载时调用 `resize(70)`。

这个 API 是迷你播放列表能真正显示的关键边界：CSS 只能控制渲染层内容，不能突破 Electron BrowserWindow 的物理高度。列表展开必须先让窗口获得足够高度，再让下拉容器占用扩高后的剩余空间。

### 2. Preload 层 — electron/preload.js

#### 暴露的 API 对象 (L55–66)

```js
miniMode: {
  enter: (alwaysOnTop) => ipcRenderer.send('mini-mode:enter', alwaysOnTop),
  exit: () => ipcRenderer.send('mini-mode:exit'),
  setAlwaysOnTop: (enabled) => ipcRenderer.send('mini-mode:set-always-on-top', enabled),
  resize: (height) => ipcRenderer.send('mini-mode:resize', height),
  onStateChange: (cb) => { /* 注册/注销 IPC 监听器 */ },                   // 当前未使用
}
```

#### IPC → DOM 事件桥接 (L140–142)

```js
ipcRenderer.on('mini-mode:state-change', (_event, isMini) => {
  document.dispatchEvent(new CustomEvent('mini-mode-state', {
    detail: isMini,
    bubbles: true,
  }));
});
```

主进程的 `webContents.send` 到达渲染进程后，被转换为 DOM CustomEvent `mini-mode-state`。App.vue 通过 `document.addEventListener` 接收，避免在组件中直接依赖 IPC。

### 3. 状态管理 — src/stores/ui.ts

#### 状态字段

```ts
interface UiState {
  isMiniMode: boolean;       // 由 IPC 事件驱动，不持久化
  miniAlwaysOnTop: boolean;  // 存 sessionStorage，仅会话内有效
}
```

#### 方法

| 方法 | 行为 |
|---|---|
| `enterMiniMode()` | 若非迷你模式，调用 `appEnv.miniMode.enter(state.miniAlwaysOnTop)` |
| `exitMiniMode()` | 若在迷你模式，调用 `appEnv.miniMode.exit()` |
| `setMiniAlwaysOnTop(enabled)` | 更新状态 + sessionStorage + 若在迷你模式即时通知主进程 |

#### 持久化策略

- `miniAlwaysOnTop`：存 `sessionStorage` key `tm_mini_always_on_top`。不跨会话保留。
- `isMiniMode`：不持久化，由 IPC 事件动态设置。窗口关闭/崩溃后重启自然回到正常模式。

### 4. MiniPlayBar 组件 — src/components/MiniPlayBar.vue

#### 布局结构

```
.mini-play-bar (position: relative; height: 100vh; overflow: hidden)
├── .mini-bar-container (height: 64px)
│   ├── .cover-wrap (36×36 封面，点击 → 退出 mini + 打开全屏)
│   ├── .song-info (flex:1，歌名+歌手，点击同上)
│   ├── .control-buttons (上一首/播放暂停/下一首)
│   └── .function-buttons (收藏/音量/播放列表/关闭)
├── .progress-bar (高度 3px，hover 高亮，点击 seek)
└── .playlist-dropdown (position: absolute; top: 67px; height 过渡)
    └── .mini-playlist-list (height: 100%; overflow-y: auto)
```

#### 播放列表下拉机制

- **始终在 DOM 中**（无 `v-if`），通过 `:class="{ open: showPlaylist }"` 控制可见性
- **打开前先扩展窗口**：`togglePlaylist()` 切换状态后，同步调用 `appEnv.miniMode.resize(360)`
- **关闭时恢复窗口**：关闭播放列表或组件卸载时调用 `appEnv.miniMode.resize(70)`
- **绝对定位**：`position: absolute; top: 67px; left: 0; right: 0; bottom: 0`，列表从进度条下方开始
- **高度来自真实窗口**：打开时 `.playlist-dropdown` 使用 `height: calc(100% - 67px)`，不再使用固定 `300px` 内容高度
- **底部贴边**：`.mini-playlist-list` 使用 `height: 100%` 和 `padding: 4px 0 0`，底部不保留额外 padding
- 双击列表项 → `playByIndex(idx)`，不自动关闭列表

#### 高度常量

| 常量 | 值 | 说明 |
|---|---:|---|
| `MINI_BAR_HEIGHT` | 70 | 紧凑态窗口高度 |
| `MINI_PLAYLIST_HEIGHT` | 360 | 播放列表展开态窗口高度 |

#### 边界原则

迷你播放列表不能只改 CSS。Electron 窗口物理高度是硬边界：如果窗口仍是 `70px`，渲染层的下拉区域即使设置 `height / max-height` 也无法显示。正确顺序是：

```
用户点击播放列表按钮
  → showPlaylist 状态切换
  → appEnv.miniMode.resize(360 / 70)
  → BrowserWindow 高度变化
  → .playlist-dropdown 按 100% 容器高度展开/收起
```

#### 列表项左侧状态栏逻辑

| 条件 | 显示 |
|---|---|
| 非当前播放 + 非 hover | 序号（idx + 1） |
| 非当前播放 + hover | 播放三角图标 |
| 当前播放 + 暂停 + hover | 播放三角图标 |
| 当前播放 + 播放中 + hover | 暂停双竖线图标 |
| 当前播放 + 播放中 + 非 hover | 3 条音浪动画 |

#### 封面加载

使用 `useBgLoaded` composable，接收 `currentPicUrl` computed getter，确保封面异步加载完成后触发 `fade-in-bg` 渐入动画。

#### 交互细节

- 封面/歌名区域点击 → `exitMiniMode()` + 100ms 延迟 → `playerStore.openExpanded()`
- 关闭按钮 → `uiStore.exitMiniMode()`
- 所有交互控件标记 `-webkit-app-region: no-drag`，其余区域 `drag` 支持窗口拖拽

```ts
function handleMiniModeState(e: Event) {
  uiStore.state.isMiniMode = !!(e as CustomEvent).detail;
}

// onMounted:
document.addEventListener('mini-mode-state', handleMiniModeState);

// onBeforeUnmount:
document.removeEventListener('mini-mode-state', handleMiniModeState);
```

## 关键设计决策

| 决策 | 理由 |
|---|---|
| 复用同一 BrowserWindow | 状态自然共享，无需跨窗口 Pinia 同步 |
| `sessionStorage` 存置顶偏好 | 仅会话内有效，重启后默认不置顶 |
| 迷你模式隐藏整个常规布局 | 减少 DOM 节点，避免隐藏元素的副作用 |
| 播放列表始终在 DOM + CSS class 控制 | 避免 `v-if` 导致的 DOM 插入/移除和布局重算 |
| 播放列表展开时调用 `miniMode.resize` | Electron 窗口高度是硬边界，必须先扩高窗口才能显示下拉内容 |
| 播放列表绝对定位脱离流 | 打开/关闭不影响 bar 容器及其他元素布局 |
| 列表高度跟随真实窗口 | `.playlist-dropdown` 使用 `height: calc(100% - 67px)`，避免固定高度造成底部留白 |
| 窗口固定 340 宽 + 高度 70~500 | 宽度固定，高度由紧凑态/播放列表态切换 |
| IPC → CustomEvent 桥接 | 组件通过标准 DOM 事件同步状态，无需依赖 Electron API |
| macOS 全屏安全处理 | 进入迷你时检测 `isFullScreen()`，先退再设置尺寸 |
| macOS 红绿灯在迷你模式隐藏 | 使用 `setWindowButtonVisibility(false)` 运行时隐藏，退出时恢复，无需修改 MiniPlayBar 布局 |

## 窗口尺寸常量

| 常量 | 值 | 说明 |
|---|---|---|
| miniWidth | 340 | 固定宽度 |
| miniHeight (紧凑态) | 70 | 默认迷你栏高度 |
| playlistHeight (展开态) | 360 | 打开播放列表后的窗口高度 |
| maxHeight | 500 | 主进程钳制上限，避免异常高度 |
| margin | 20 | 距屏幕边缘距离 |
| 恢复最小宽高 | 1100×700 | 退出迷你时恢复 |

## 播放列表下拉：窗口高度与底部贴边

**问题背景**：迷你模式的紧凑窗口只有 `70px` 高。播放列表下拉如果只改渲染层 CSS，而不调整 Electron BrowserWindow 高度，内容会被窗口物理边界裁掉，看起来就是“打不开”。如果用固定列表高度，又会在不同窗口高度下产生底部留白。

**当前方案**：

| # | 措施 | 说明 |
|---|------|------|
| 1 | 保留元素常驻 DOM | 播放列表不使用 `v-if`，通过 `open` class 控制状态 |
| 2 | 状态切换时同步窗口高度 | 打开 `resize(360)`，关闭 `resize(70)` |
| 3 | 下拉区占满真实剩余高度 | `.playlist-dropdown.open { height: calc(100% - 67px); }` |
| 4 | 列表底部不留 padding | `.mini-playlist-list { padding: 4px 0 0; }`，底部直接贴到容器边缘 |

**维护要求**：

- 不要把播放列表重新改回纯 CSS 展开；迷你模式受 BrowserWindow 物理高度限制。
- 不要重新使用固定 `max-height: 300px` 作为列表真实高度；这会重新引入底部留白或裁切。
- 调整播放列表展开高度时，优先改 `MINI_PLAYLIST_HEIGHT`，并确认不超过主进程 `mini-mode:resize` 的 `500` 上限。
