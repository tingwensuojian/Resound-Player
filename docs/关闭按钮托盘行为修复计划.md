# 关闭按钮与系统托盘行为修复计划

> 对应问题：点击主界面关闭按钮（×）后，窗口消失但托盘残留，且无法从托盘重新打开主界面。
> 关联规范：`AGENTS.md` 中"桌面应用「主窗口关闭按钮（×）」通用行为规范"
> 目标文件：`electron/main.js`

> **注意**：文档中行号基于当前 `main.js`，后续有其他改动时可能漂移，请以代码上下文为准。

---

## 一、问题诊断

### 1.1 根因：错误使用了 isQuitting 标记

`electron/main.js` 第 432 行：

```js
if (process.platform !== 'darwin') {
  win.on('close', (event) => {
    if (!app.isQuitting()) {   // 这个 API 不存在！
      event.preventDefault();
      win.minimize();
    }
  });
}
```

`app.isQuitting()` 在 Electron 42 中不存在（electron.d.ts 中搜不到）。
调用结果是 `undefined`，`!undefined` 恒为 `true`，导致：

- **关闭按钮永远被拦截**，只执行 `win.minimize()` 最小化到任务栏
- **托盘"退出"菜单也被拦截** —— `app.quit()` 触发 close 事件，同样被 preventDefault 住，进程永远无法退出
- 用户只能靠任务管理器杀进程

### 1.2 次要问题：最小化而非隐藏

当前用 `win.minimize()` 把窗口最小化到任务栏。
音乐播放器标准行为是"关闭即隐藏到托盘，仅留托盘图标"，应改为 `win.hide()`。

### 1.3 唤醒路径不匹配隐藏状态

`showMainWindowFromTray()` 和 `handleActivateWindow()` 都用 `w.isMinimized()` 判断窗口状态。
`win.hide()` 后的窗口 `isMinimized()=false`、`isVisible()=false`，判断条件需要改成 `!w.isVisible()`。

## 二、改动清单

### 2.1 [P0] 添加全局 isQuitting 标记

**位置**：`electron/main.js`，全局变量区域（第 1061 行 `let mainTray` 附近）

新增：

```js
let isQuitting = false
```

**位置**：`electron/main.js` 第 898 行 `before-quit` 事件

改前：

```js
app.on('before-quit', () => {
  killAllServices(serviceChildren);
});
```

改后：

```js
app.on('before-quit', () => {
  isQuitting = true;
  killAllServices(serviceChildren);
});
```

**为什么这一处改动管三条退出路径**：

1. **托盘点"退出"**：`isQuitting = true` → `app.quit()` → `before-quit` 再次置位（安全冗余）→ 各窗口 close 事件发现 `isQuitting = true` → **不再拦截** → 正常退出
2. **系统菜单（文件 > 退出 / Ctrl+Q）**：同样走 `app.quit()`，同上路径
3. **`window-all-closed` 事件**（第 894 行）：非 macOS 上自动调 `app.quit()`，同上路径

### 2.4 [P1] 修改 showMainWindowFromTray：适应 hide 状态

**位置**：`electron/main.js` 第 834-861 行

改后要点：

1. 把 `if (w.isMinimized()) w.restore()` 改为 `!w.isVisible()` 优先判断
2. 消除 win32 平台分支中与前置判断重复的 `w.show()`

```js
function showMainWindowFromTray() {
  console.log('[tray] clicked');
  var existing = BrowserWindow.getAllWindows().filter(function(w) { return !w.isDestroyed(); });
  if (existing.length > 0) {
    var w = existing[0];
    if (!w.isVisible()) {
      // hide() 后的窗口：show 即可恢复
      if (process.platform === 'win32') {
        w.show();
        try { app.focus(); } catch(e) {}
      } else if (process.platform === 'darwin') {
        w.setAlwaysOnTop(true);
        try { app.focus(); } catch(e) {}
        w.show();
        w.focus();
        setTimeout(function() {
          try { if (!w.isDestroyed()) w.setAlwaysOnTop(false); } catch(e) {}
        }, 200);
      } else {
        w.show();
        w.focus();
      }
    } else if (w.isMinimized()) {
      w.restore();
      // 最小化恢复后同样需要聚焦
      if (process.platform === 'win32') {
        try { app.focus(); } catch(e) {}
      }
    } else {
      w.focus();
    }
    return;
  }
  bootstrap();
}
```

#### main.js 改动

**配置持久化**（沿用 desktopLyric 的 JSON 文件模式）：

```js
// ── 关闭行为配置 ──
const CLOSE_BEHAVIOR_FILE = path.join(app.getPath('userData'), 'close-behavior.json')

let closeBehaviorConfig = { mode: 'hide' }  // 'hide' | 'quit'

function loadCloseBehaviorConfig() {
  try {
    if (fs.existsSync(CLOSE_BEHAVIOR_FILE)) {
      closeBehaviorConfig = { ...closeBehaviorConfig, ...JSON.parse(fs.readFileSync(CLOSE_BEHAVIOR_FILE, 'utf-8')) }
    }
  } catch (e) {
    console.error('[close-behavior] load failed:', e)
  }
}

function saveCloseBehaviorConfig() {
  try {
    fs.writeFileSync(CLOSE_BEHAVIOR_FILE, JSON.stringify(closeBehaviorConfig), 'utf-8')
  } catch (e) {
    console.error('[close-behavior] save failed:', e)
  }
}

function getCloseBehaviorConfig() {
  return { ...closeBehaviorConfig }
}

function setCloseBehaviorConfig(config) {
  closeBehaviorConfig = { ...closeBehaviorConfig, ...config }
  saveCloseBehaviorConfig()
  // 广播到所有窗口
  BrowserWindow.getAllWindows().forEach((w) => {
    if (!w.isDestroyed()) w.webContents.send('close-behavior:config-changed', { ...closeBehaviorConfig })
  })
}
```

#### 加载时序

```
bootstrap()
  ├─ loadDesktopLyricConfig()
  ├─ loadTrayLyricConfig()
  └─ loadCloseBehaviorConfig()    ← 新增，在 createMainWindow 之前调用
```

确保 `closeBehaviorConfig` 在窗口创建和 close 事件注册之前就已加载，避免第一次关闭时读到默认值。

#### 切换行为完整链路

```
用户拨动开关
  ↓
switchState.closeToTray 变化
  ↓
watch → window.appEnv.closeBehavior.setConfig({ mode: 'hide'|'quit' })
  ↓
ipcMain.handle('close-behavior:set-config')
  ↓
setCloseBehaviorConfig() → 写 JSON 文件 + 广播 config-changed
  ↓
用户点击关闭按钮
  ↓
close 事件触发
  ↓
isQuitting 为 false → check closeBehaviorConfig.mode
  ├─ 'hide' → event.preventDefault() + win.hide()
  └─ 'quit' → isQuitting = true + win.close()（真正退出）
```

#### 异常兜底

- JSON 文件损坏或不存在 → 默认 `mode: 'hide'`，不抛出异常
- 非桌面端 → 设置项不可见（通过 `isTabAvailable` 模式，仅桌面端显示）

## 四、风险与注意事项

- `win.hide()` 后 `isVisible()=false`、`isMinimized()=false` —— 所有判断窗口状态的逻辑都要同步排查
- `isQuitting = true` 要加在 `before-quit` 事件的最前面，确保 close 事件触发时标记已生效
- `window-all-closed`（第 894 行）不会触发（close 被拦截了），不需要改动
- 桌面歌词窗口是独立的 BrowserWindow，关闭主窗口不应关闭它
- 改完后需要完整验证托盘右键菜单的每一条路径，特别是"退出"路径
