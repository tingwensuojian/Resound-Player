# 2026-06-07 迷你模式黑屏首帧

## Symptom

进入迷你模式时，迷你窗口会先显示一小段黑色/深色画面，然后才显示正常迷你播放条。

## Root cause

问题有两层：

1. `electron/main.js` 原先在 `ready-to-show` 事件中立即 `miniWin.show()`，并在创建迷你窗口后立刻 `win.hide()`。实测 `ready-to-show` 到达时，Vue DOM 与 `.mini-play-bar` 可能已经存在、CSS 计算结果也已是正常背景，但 Chromium compositor 仍可能短暂输出 BrowserWindow 的 `backgroundColor: '#1a1a2e'` 首帧。
2. 用户复测后仍有黑屏。暗色主题探针确认最终可见黑屏来自 `src/components/MiniPlayBar.vue` 的根容器动画：`.mini-play-bar` 使用 `animation: anFadeUp 0.38s both`，而 `anFadeUp` 的起始态是 `opacity: 0`。主进程门控后，显示瞬间 `.mini-play-bar` 仍处于 opacity `0.27 → 0.56 → 0.97` 的动画期，用户看到的就是 body/window 的深色底。

## Fix

- `src/mini-main.ts` 在 Vue mount 后等待 `nextTick()` 和两帧 `requestAnimationFrame`，再通过 preload 通知主进程 renderer 首帧已稳定。
- `electron/preload.js` 新增 `miniMode.rendererReady()` IPC。
- `electron/main.js` 同时等待 Electron `ready-to-show` 和 renderer-ready 两个信号，然后才显示迷你窗口并隐藏主窗口。
- 如果 renderer-ready 3 秒内未到达，取消迷你模式并恢复主窗口，避免卡在半切换状态。
- `src/components/MiniPlayBar.vue` 移除 `.mini-play-bar` 根容器的 `anFadeUp` 入场动画，保证迷你窗口首个可见帧就是完整播放条。

## Evidence

修复前探针观察到：`dom-ready` / `did-finish-load` 时 `hasMini: true` 且 body computed background 为浅色，但截图均值仍接近深色 `[25,23,22]`，说明暴露的是窗口背景首帧。

第一阶段修复后探针观察到：`ready-to-show` 约 139ms，`renderer-ready` 约 147ms；门控后截图均值为浅色 `[249,250,249]`，显示后 50ms 仍为正常 UI 色 `[238,245,239]`。但暗色主题下仍能复现黑屏。

最终修复前暗色探针观察到：`ready-to-show` / `renderer-ready` 时 `.mini-play-bar` 已存在，但 opacity 约 `0.273`，显示后 120ms opacity 仍约 `0.564`，截图均值约 `[24,22,20]`。

最终修复后暗色探针观察到：`ready-to-show` / `renderer-ready` / 显示后 `0ms` 起 `.mini-play-bar` 均为 opacity `1`、transform `none`、animation `none 0s`。

## Verification

- `npm run build:web` 通过。
- `node --check electron/main.js && node --check electron/preload.js` 通过。
