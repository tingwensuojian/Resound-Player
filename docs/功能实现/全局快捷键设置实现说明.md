# 全局快捷键设置实现说明

## 概述

为 Resound-Player 增加了完整的双平台（macOS / Windows）快捷键设置系统，包含 8 个固定功能的快捷键自定义、全局快捷键注册、应用内快捷键监听、桌面端 SQLite 持久化、以及设置页完整的 UI 交互。

## 架构

```
+---------------------+     IPC (invoke/handle)     +----------------------+
|  渲染进程 (Renderer) |<-------------------------->|  主进程 (Main)       |
|                     |  shortcut:get-config        |                      |
|  useShortcutKeydown  |  shortcut:save-config       |  ShortcutManager     |
|  shortcutStore       |  shortcut:reset-defaults    |  |                  |
|  ShortcutInput       |  shortcut:set-global-enabled|  +- SQLite (sql.js)  |
|  ShortcutSetting     |  shortcut:set-media-keys-   |  +- globalShortcut  |
|                     |    enabled                   |  +- Media Keys      |
|                     |  shortcut:action (-> 广播)   |                     |
+---------------------+                             +----------------------+
```

## 数据流

### 保存快捷键

ShortcutInput (按键捕捉) -> emit('update:modelValue') -> ShortcutSetting.onShortcutChange() -> shortcutStore.saveShortcut() -> window.appEnv.shortcutApi.saveConfig() -> ipcRenderer.invoke('shortcut:save-config') -> ShortcutManager.handleSaveConfig() -> SQLite INSERT OR REPLACE -> refreshAll() -> globalShortcut.register(newAccelerator)

### 全局快捷键触发

用户按键 -> globalShortcut 回调 -> ShortcutManager.sendAction(actionId) -> win.webContents.send('shortcut:action', actionId) -> preload onShortcutAction -> shortcutStore.dispatchAction() -> playerStore API

### 应用内快捷键触发

用户按键 -> window 'keydown' 事件 -> useShortcutKeydown 处理器 -> 匹配 appShortcut 配置 -> shortcutStore.dispatchAction() -> playerStore API

## 关键实现细节

### 1. 平台无关的快捷键存储格式

所有快捷键组合使用 ShortcutCombo 接口（{key, modifiers}）存储，不依赖平台。展示时由工具函数格式化：
- macOS：符号映射 meta->Cmd, ctrl->Ctrl, alt->Option, shift->Shift，修饰符间无空格
- Windows：文本映射 meta->Win, ctrl->Ctrl, alt->Alt, shift->Shift，修饰符间加空格

主进程注册时通过 toElectronAccelerator() 转为 Electron accelerator 格式（如 Alt+Command+P）。

### 2. 默认值按平台实时计算

getDefaultShortcuts(platform) 接收平台参数，实时返回当前平台默认值。不存储默认值在 SQLite 中，避免跨平台读错。

### 3. 两步初始化

shortcutManager.init() 必须先于 createMainWindow()，否则渲染进程启动后的 loadConfig() IPC 调用会因 handler 未注册而失败。

### 4. Reactive Proxy 深拷贝

state.shortcuts 是 Pinia reactive proxy，通过 ipcRenderer.invoke 发送前必须深拷贝为纯对象，否则 Structured Clone Algorithm 会抛 "An object could not be cloned" 错误。buildConfig() 中对每个 shortcut 项做深拷贝。

### 5. 应用内快捷键的生命周期

useShortcutKeydown() 在 App.vue 顶层 setup 中调用（非 onMounted 内），直接注册 window.keydown 监听。组件卸载时通过 onUnmounted 清理。同时初始化 loadConfig() 和 startListening()。

### 6. Web 端隔离

快捷键设置 tab 通过 isTabAvailable('shortcuts') -> platform.isDesktop 门控，Web 端完全不显示。shortcutStore 所有 IPC 调用有 window.appEnv guard。

### 7. macOS 菜单快捷键冲突

setupChineseMenu() 中 role: 'reload' 的默认 accelerator 为 CmdOrCtrl+R，拦截渲染进程 keydown 事件。解决：给 reload 和 forceReload 菜单项加上 accelerator: '' 移除键盘快捷键。

详情见同目录下的专门文档。

### 8. 遮罩层统一

冲突对话框和恢复默认确认弹窗使用 <Teleport to="body">，确保 position: fixed 基于 viewport 定位。遮罩层背景统一为 rgba(0,0,0,0.25)。

### 9. 快捷键符号渲染

ShortcutInput 字体改用系统字体 -apple-system, sans-serif，替代 monospace 字体栈。字号从 13px 提升到 16px。

## 快捷键录入组件 (ShortcutInput)

| 状态 | 表现 |
|------|------|
| idle | 展示格式化文本；null 时显示 "-" |
| recording | 聚焦进入录制模式，提示"按下快捷键..."，背景高亮 |
| 按键捕获 | preventDefault 阻止默认行为；纯修饰键忽略；非修饰键捕获生成 ShortcutCombo |
| Escape | 取消录制，恢复旧值 |
| Backspace/Delete | 清空快捷键 |
| 空值 | 红色边框标记 |

### 10. 单曲循环模式下快捷键切歌修复

**问题**：当播放模式为「单曲循环」时，按 Ctrl+→（下一首快捷键）会重新播放当前歌曲，而不是跳到下一首。
这是因为 playerStore.next() 在单曲循环模式下会调用 playByIndex(state.currentIndex) 重新播放当前曲目。

**修复**：

1. src/stores/player.ts — 
next() 函数新增 forceNext 可选参数：
   - 当 forceNext: true 时，跳过单曲循环的 replay 逻辑，正常跳到下一首
   - forceNext 未传或为 false 时，行为不变（自然播完仍会循环当前曲目）

2. src/stores/shortcutStore.ts — dispatchAction('nextTrack') 调用 
next({ forceNext: true })：
   - 确保快捷键触发时永远切歌，不受播放模式影响

**影响**：
- 快捷键 Ctrl+→ / Cmd+→ 在所有播放模式下都正确跳到下一首
- 自然播完时单曲循环的行为不变
- prevTrack（上一首）不受影响，其实现本就没有单曲循环检查

### 11. Windows Space 键显示修复

**问题**：快捷键设置页面中，Space 键在 Windows 上显示为英文「Space」，macOS 上正确显示为中文「空格」。

**修复**：
- src/utils/shortcutPlatformUtil.ts — KEY_DISPLAY 映射中 Space 的 win 值从 'Space' 改为 '空格'

**影响**：播放/暂停快捷键（全局和应用内）在 Windows 上正确显示为「空格」。

### 12. 全局快捷键冲突检测（系统占用检测）

**背景**：全局快捷键的默认组合（Alt+Ctrl+方向键等）容易和系统或其他软件的热键冲突，但之前没有视觉反馈。

**实现原理**：

注册状态追踪由主进程 shortcutManager.js 的 #registerOne() 完成，利用 Electron globalShortcut.register() 的返回值（Windows 上基于 RegisterHotKey API）判断快捷键是否注册成功：

- true → 注册成功，状态标记为可用
- false → 注册失败（已被其他也使用 RegisterHotKey 的软件占用），标记为冲突

**数据流**：

`
#registerOne() → #regStatus Map<actionId, boolean>
    ↓
refreshAll() → #broadcastRegStatus()
    ↓               ↓
IPC handler       webContents.send
'shortcut:get-    'shortcut:reg-status-changed'
reg-status'
    ↓               ↓
shortcutStore.loadRegStatus() / onRegStatusChanged 监听
    ↓
ShortcutSetting 传入 :conflict 到全局快捷键列的 ShortcutInput
    ↓
ShortcutInput 显示红框 + 「热键被占用」文字
`

**涉及文件**：

| 文件 | 改动 |
|------|------|
| electron/main/shortcutManager.js | 新增 #regStatus Map、#registerOne/#unregisterOne/refreshAll 中维护状态、IPC handler shortcut:get-reg-status、#broadcastRegStatus 广播 |
| electron/preload.js | 新增 getRegStatus() invoke + onRegStatusChanged() 监听 |
| src/stores/shortcutStore.ts | state 新增 regStatus 字段、loadRegStatus() 方法、saveShortcut/resetDefaults/loadConfig 后自动拉取、startListening 中注册监听 |
| src/components/ShortcutInput.vue | 新增 conflict: boolean prop、冲突时输入框红色边框样式 |
| src/views/setting/ShortcutSetting.vue | 全局快捷键列传入 :conflict、st-cell-shortcut 增加 gap 布局、新增 .conflict-hint 样式 |
| electron/main.js | registerAll() 后调用 broadcastRegisterStatus() 确保初始化后立即广播 |

**已知限制**：

系统占用检测基于 Windows RegisterHotKey API，只能检测到同样使用该 API 的其他软件（如系统热键、Visual Studio、截图工具等）的冲突。

部分软件（如网易云音乐、QQ 音乐等）使用低层键盘钩子（SetWindowsHookEx）实现全局快捷键，不会在 RegisterHotKey 层面产生冲突，我们的检测机制无法覆盖此类场景。
