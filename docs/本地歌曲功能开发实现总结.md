### 根部重构详解

**问题**：`LocalArtistsPage.vue`、`LocalAlbumsPage.vue`、`LocalFoldersPage.vue` 三个子视图各自复制了 `playTrack`、`addToPlaylist` 等事件处理函数，但唯独缺失 `play-next` 和 `show-in-folder` 事件监听，导致"下一首播放"和"定位到目录"在歌手/专辑/文件夹页完全无响应。`LocalSongsPage.vue` 的"添加至歌单"弹窗使用不可靠的 `trackCount` 字段显示歌单歌曲数。

**修复策略**：不逐个页面修补事件绑定，而是萃取共享逻辑新建一级模块：

- **`useLocalTrackActions.ts`**：提供统一的 `playTrack`、`playNext`、`addToPlaylist`、`showInFolder`、`uploadToCloud`、`showLocalAlbum`、`showOnlineAlbum` 方法，以及 `showPlaylistPicker`、`confirmPlaylist`、`cancelPlaylistPicker` 弹窗状态管理。
- **`PlaylistPickerDialog.vue`**：可复用的"添加至歌单"弹窗组件，使用 `pl.tracks?.length || 0` 从源头取值。
- 三个子视图页面（Artist/Album/Folder）替换内联复制代码为 `<PlaylistPickerDialog>` + `@track-actions` 事件委托给 composable。
- `LocalSongsPage.vue` 替换内联对话框为共享 `PlaylistPickerDialog`，并删除对应的重复 CSS。

### 上传至云盘重复检测详解

**根因**：`cloud_import.js` 调用 `/api/cloud/upload/check/v2` 获取 `upload` 字段（0=可导入、1=已在云盘、2=不可导入），但原代码无视 `upload` 值一律发起导入请求。对于已在云盘的文件，导入接口仍返回 `code: 200`，前端误以为上传成功。

**修复**：
1. 修改 `cloud_import.js`：读取 `uploadFlag = (res.body.data[0] && res.body.data[0].upload) || 0`，若 `uploadFlag === 1` 则直接返回 `{ body: { code: 200, duplicate: true, message: '文件已在云盘' } }`，不发起实际导入请求。
2. 安装 `patch-package`，添加 `postinstall` 脚本，生成补丁文件固化此修改。
3. 前端四个 `uploadToCloud` 实现点（`LocalSongsPage.vue`、`useLocalTrackActions.ts`、`LocalPlaylistDetailPage.vue`、`SongActions.vue`）在响应中检查 `duplicate` 字段，若为 true 则显示"文件已在云盘" info toast 并提前返回。

## 📦 v3.5 变更记录（2026-05-24）

> 目标：修复万级曲库批量封面加载 IPC 消息体过大导致封面全部缺失。

| 变更 | 文件 | 说明 |
|------|------|------|
| **分片批量封面加载** | `localMusic.ts` | `lazyLoadCovers()` 中 `getCoversBatch()` 从一次性全量调用改为每 50 首分片调用，每片完成后立即递增 `_coverVersion` 触发 UI 逐批刷新 |

**根因**：原 `getCoversBatch` 将全部封面 base64 数据收集到一个数组中通过单次 IPC 返回。对于大量曲目（如万级库），总 payload 可达数百 MB，超出 Electron IPC 结构化克隆限制或导致渲染进程长时间阻塞，封面加载静默失败。而「最近添加」使用逐首 `getCover()`，每次 IPC 仅返回单张封面（≤500KB），不受影响。

**修复**：将一次性全量调用改为每 50 首分片调用 `getCoversBatch()`，每片 payload ≤25MB，安全可控。每片完成后立即写入 `coverUrl` 并递增 `_coverVersion`，实现 UI 逐批刷新。

└──────────────────────────────────────────────────────────────┘

### 核心原则

- **仅桌面端（Electron）**：Web 端不提供本地歌曲功能
- **platform.isDesktop 守卫**：所有本地入口、路由、Store 方法都需加守卫
- **播放方案**：通过 IPC (`local:read-file`) 读取文件内容，在渲染进程创建 `Blob` + `URL.createObjectURL`，避免 `local://` 协议的 CORS 问题

| `src/App.vue` | 路由注册 + platform.isDesktop 守卫 + `handleLocalNavigate` 本地页面路由 |

## 3. 存储方案

采用 **SQLite 文件存储**（`local-music.sqlite` 位于 Electron `userData` 目录），通过 `sql.js` (WASM SQLite) 实现 ACID 事务和索引查询。

### 演进历史

| 方案 | 版本 | 问题 | 结论 |
|-----|------|------|------|
| `better-sqlite3` | 初始 | Electron 42 的 V8 API 变更导致 `electron-rebuild` 编译失败 | ❌ 放弃 |
| **JSON 文件** | 中间过渡 | 写入不安全（无原子性、崩溃后半写文件丢数据） | ❌ 放弃 |
| `sql.js` (WASM SQLite) | **当前** | 零原生依赖，纯 WASM 在 Electron 主进程稳定工作 | ✅ 采用 |

### 数据库 Schema (4 表 + 5 索引)

```sql
tracks:          id(PK), path(UNIQUE), title, artist, album, albumArtist,
                 duration, bitrate, sampleRate, trackNo, discNo, genre,
                 year, coverPath, fileSize, mtime, hasLyrics, createdAt, updatedAt
                 → idx_tracks_path, idx_tracks_title, idx_tracks_artist, idx_tracks_album

scan_dirs:       id(PK AUTOINCREMENT), path(UNIQUE), label, lastScan

playlists:       id(PK), name, description, coverPath, createdAt, updatedAt

playlist_tracks: (playlistId, trackId)(PK), sortOrder, addedAt
                 → FOREIGN KEY → playlists(id) ON DELETE CASCADE, tracks(id) ON DELETE CASCADE
                 → idx_playlist_tracks_playlist

local_lyric_matches: localTrackId(PK), localPath, cloudSongId, cloudSongName,
                     cloudArtists, cloudAlbum, cloudDuration, matchMode,
                     createdAt, updatedAt
                     → idx_local_lyric_matches_path
```

### 读写机制

- **写入**：通过 `#enqueueWrite(fn)` 串行队列，所有写操作在 Promise 链中排队执行
- **原子持久化**：`#atomicPersist()` → `db.export()` 导出完整 SQLite 二进制 → `writeFileSync(.tmp)` → `renameSync(.tmp → .sqlite)` — POSIX 原子替换
- **崩溃恢复**：WAL journal 模式 + try/catch 保护，JSON 方案时的半写文件问题已解决
- **查询**：SQL 索引查询（`COLLATE NOCASE` 排序），取代 JSON 方案的 JS `filter`
- **数据迁移**：首次启动时自动从旧 `local-music.json` 迁移到 SQLite

## 5. 本地歌曲手动云端歌词匹配

目标：本地歌曲没有外部歌词文件时，允许用户在播放页手动搜索云端歌曲并保存匹配关系，后续播放同一首本地歌曲时复用云端歌词。

### 入口与交互

- 入口位于展开播放页底部控制区，靠近「均衡器」按钮。
- 仅当前播放歌曲 `source === 'local'` 时显示「歌词匹配」按钮。
- 弹窗默认搜索关键词为「本地歌曲名 + 歌手」。
- 用户从搜索结果中选择云端歌曲后，保存前会检查该云端歌曲是否存在可用歌词。
- 已存在匹配时，弹窗展示当前匹配，并支持「重新匹配」和「取消匹配」。
- 搜索结果右侧时长会与当前本地播放时长做显示文本级比较；如果两侧显示时长完全一致（如同为 `3:58`），该时长会显示为独立金黄色胶囊，用于提示更可能是高匹配结果。
- 如果已保存的云端匹配后续解析不到歌词，弹窗会提示“当前保存的云端匹配暂无可解析歌词，请重新选择一个结果”，控制台也会输出 `[lyrics] saved local lyric match has no parsable lyrics` 诊断日志。

### 歌词加载优先级

本地歌曲歌词加载顺序：

1. 读取本地外部歌词文件：同目录同名 `.lrc` / `.yrc` / `.ttml`。
2. 如果没有本地歌词，读取 `local_lyric_matches` 中保存的 `cloudSongId`。
3. 使用保存的 `cloudSongId` 请求 `/lyric/new`，失败或为空时回退旧歌词 API。
4. 如果没有匹配记录，不再把本地歌曲 md5 字符串强制转成数字 ID 请求在线歌词。

### 持久化规则

- 匹配数据保存在 SQLite `local_lyric_matches` 表。
- 主键为 `localTrackId`，重新匹配使用 `ON CONFLICT(localTrackId) DO UPDATE` 覆盖旧记录。
- 删除本地歌曲、按目录删除、清空本地曲库时，会同步删除相关匹配记录。
- 保存或取消匹配后，渲染进程通过 `notifyLocalLyricMatchUpdated()` 更新全局刷新版本号，所有 `useLyrics()` 实例都会重新校验当前本地歌曲匹配；旧的 `local-lyric-match-updated` DOM 事件仅作为兼容入口。

### 添加新 IPC 的步骤

1. **DB 层** (`LocalMusicDB.js`) — 添加查询方法
2. **IPC 层** (`localMusicIpc.js`) — 注册 `ipcMain.handle`
3. **Preload** (`preload.js`) — `contextBridge` 暴露 API
4. **类型** (`platform.ts`) — `LocalApi` 接口添加签名
5. **Store** (`localMusic.ts`) — 添加调用方法
6. **重启 Electron**

## 6. 平台检测与守卫

### `platform.isDesktop` 检测逻辑

```typescript
// src/utils/platform.ts
get isDesktop(): boolean {
    if (typeof window === 'undefined') return false
    // Electron preload 注入 appEnv
    if (!!(window as any).appEnv?.isDesktop) return true
    // 降级：UA 检测
    return typeof navigator !== 'undefined' && navigator.userAgent.includes('Electron')
}
```

### 前置条件：preload 脚本

`electron/preload.js` 必须使用 **CommonJS** (`require`) 而非 ESM (`import`)：

```js
// ✅ Electron 沙盒环境兼容
const { contextBridge, ipcRenderer } = require('electron');

// ❌ 不支持（Sandbox 模式下 SyntaxError）
import { contextBridge, ipcRenderer } from 'electron';
```

### 守卫应用位置

| 位置 | 守卫方式 |
|---|---|
| `App.vue` 路由 | `v-if="activePage === 'local-xxx' && platform.isDesktop"` |
| `Sidebar.vue` 菜单 | `...(platform.isDesktop ? [{...}] : [])` |
| Store 方法 | `if (!platform.localApi) return` |
| SettingsPage 设置项 | `!platform.isDesktop` 时从 `currentGroups` 过滤 |
| `apiBaseUrl` | Dev 模式返回 `/api`（走 Vite 代理），打包后返回直连 URL |

### 扫描目录持久化与历史恢复

扫描目录采用 **SQLite `scan_dirs` + localStorage 兼容兜底** 的双层策略：

- 新增 `LocalMusicDB.upsertScanDir/listScanDirs/removeScanDir`，扫描、添加目录、移除目录时同步维护 `scan_dirs`
- `localMusic.loadDirectories()` 优先从 `local:list-scan-dirs` 读取 DB 目录，DB 为空时再读旧版 `local_music_dirs`
- 旧版本可能只留下 `tracks`，没有留下扫描目录；此时 `loadTracks()` 会从歌曲 `path` 反推根目录，回填 `state.directories`
- 反推结果会同步写回 localStorage 和 SQLite，解决“歌曲正常显示，但概览扫描目录/目录树文件数为空”的历史数据问题
- 目录树 `folderTree` 仍保留从歌曲路径反推的 UI 兜底，避免目录记录短暂缺失时页面空白

### 目录树菜单

目录标签左栏目录树支持目录节点菜单：

- 单击目录：选择目录并过滤右侧歌曲列表
- 双击目录：弹出本地菜单，当前菜单项为「打开文件夹」
- 右键目录：弹出同一菜单，不显示系统原生右键菜单
- 点击「打开文件夹」：通过 `local:open-folder` → Electron `shell.openPath()` 打开系统文件夹

因为项目全局禁止复制，`src/main.ts` 会拦截 `selectstart/contextmenu`。目录树容器使用 `data-allow-dblclick-gesture="true"` 白名单，仅放行目录树完成双击/右键菜单手势；`copy/cut/Ctrl+C` 仍然保持全局拦截。

### 播放队列与统一播放事务更新

本地音乐的“下一首播放”不再直接修改 `playerStore.state.playlist.splice()`，统一调用：

```ts
playerStore.insertNext(song)
```

这样可以保证：

- 插入队列后同步主窗口 runtime snapshot
- 迷你窗口播放列表立即得到一致队列
- 播放队列变更会持久化
- 本地歌曲和在线歌曲 / 播客混合队列切换时，只有真实 `audio.src` 切换成功后才更新当前播放曲目

本地歌曲播放对象会携带 `source: 'local'`、`path`、`duration`，播放器通过 `local:id:path` 作为播放资源身份，避免本地歌曲与在线歌曲 ID 碰撞导致歌词或迷你歌词复用旧数据。

### 新增页面

```

2. src/App.vue 中:
   - import LocalMyNewPage
   - 添加 v-else-if="activePage === 'local-my-new' && platform.isDesktop"
3. src/components/Sidebar.vue 中:
   - 添加 { key: 'local-my-new', label: '...', icon: ... }
4. 如果涉及 IPC, 执行上面的新增 IPC 步骤
5. lint + build 验证
```

### 新增 DB 字段/索引

```sql
-- SQLite: 使用 ALTER TABLE 添加字段
ALTER TABLE tracks ADD COLUMN newField TEXT NOT NULL DEFAULT '';
-- 或直接修改 SCHEMA 常量中的 CREATE TABLE 语句（对已有表无效，仅新创建的表生效）
```

> 迁移指南：对已有数据库的字段变更需编写迁移 SQL，通过 `#db.run()` 在应用启动时执行。

## 附录：依赖

| 包 | 用途 | 位置 |
|---|---|---|
| `music-metadata` | 音频元数据解析 | 主进程 |
| `jschardet` + `iconv-lite` | LRC 文件编码检测 (GBK→UTF-8) | 主进程 |
| `sql.js` | SQLite WASM 引擎（零原生依赖） | 主进程 |

> **注意**：当前存储方案为 SQLite（通过 `sql.js` WASM 引擎），纯 JavaScript 实现，无需原生模块编译。`electron-rebuild` 无需运行。仅当 Electron 版本升级后 `sql.js` 的 WASM 加载失败时需要检查兼容性。
