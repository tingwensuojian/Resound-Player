# 吸顶栏实现说明

本项目详情页的吸顶栏采用 **`position: sticky` + CSS calc 驱动**方案，滚动位置通过 RAF 映射为 `--sticky-progress`（0→1），驱动背景色/毛玻璃/内容动画的连续渐变，实现类似网易云音乐的渐进式置顶缩放效果。

---

## 一、架构层次

```
独立模式（如 PlaylistDetailPage）:
  .content::before                   ← 唯一 blur 背景来源（App.vue）
    └─ .playlist-detail-page         ← 详情页根节点（仅负责布局，不再自身滚动）
         ├─ .playlist-detail-back    ← 返回按钮，progress 驱动 opacity 淡出
         ├─ DetailStickyHeroHeader   ← 头部区域（progress 驱动折叠）
         └─ .detail-scroll-host      ← 唯一滚动宿主（overflow-y: auto）
              └─ .playlist-detail-body

嵌入模式（UserSplitView 右侧面板）:
  .content::before                   ← 唯一 blur 背景来源（App.vue）
    └─ .split-stage                  ← CSS Grid 分屏容器
         ├─ .left-panel              ← 左侧用户列表
         └─ .detail-panel            ← 右侧详情面板（overflow: hidden; height: 100%; padding-top: 0）
              └─ .detail-body-wrap   ← 内容包裹层（height: 100%）
                   └─ .playlist-detail-page.playlist-detail-page--embedded
                        ├─ .playlist-detail-back    ← 仅独立模式出现；用户页右侧 5 类详情无返回按钮
                        ├─ DetailStickyHeroHeader.detail-sticky-header--embedded
                        └─ .detail-scroll-host      ← 唯一滚动宿主
                             └─ .playlist-detail-body
```

## 三、滚动进度机制

### 3.1 滚动 → progress 映射

```typescript
const PROGRESS_DISTANCE = embedded ? 120 : 324;

function update() {
  const st = scrollHost.scrollTop;
  const progress = Math.max(0, Math.min(1, st / PROGRESS_DISTANCE));
  root.style.setProperty('--sticky-progress', String(progress));
}
```

- `progress = 0`：完全展开，背景透明
- `progress = 1`：完全折叠，背景纯色 `var(--bg-solid)`
- 嵌入模式（UserSplitView 右侧面板）使用 120px 而非 324px，因面板高度有限

### 3.2 progress 驱动的 CSS 属性

```css
.playlist-detail-header-wrap {
  background: color-mix(in srgb, var(--bg-solid) calc(var(--sticky-progress, 0) * 100%), transparent);
  backdrop-filter: blur(calc(var(--sticky-progress, 0) * 10px)) saturate(calc(1 + var(--sticky-progress, 0) * 0.32));
}
```

| progress | 背景 | backdrop-filter | 封面 scale | 封面 translateY |
|---|---|---|---|---|
| 0 | 完全透明 | blur(0) | 1.0（原始大小） | 0 |
| 0.5 | 50% `var(--bg-solid)` | blur(5px) | 0.9 | -8px |
| 1 | 100% `var(--bg-solid)` | blur(10px) | 0.8 | -16px |

### 3.3 滚动事件处理

```typescript
function onScroll(): void {
  cancelAnimationFrame(rafId);
  rafId = requestAnimationFrame(() => update());
}
```

使用 `requestAnimationFrame` 每帧写入 1 个 CSS 变量（`--sticky-progress`），delta < 0.005 时跳过写入。

滚动监听优先绑定组件内显式 `ref` 指向的 `.detail-scroll-host`，避免 `KeepAlive`、分屏详情或多详情页并存时通过全局 `querySelector` 串绑到错误节点。

### 3.4 虚拟列表协同

所有详情页歌曲列表统一使用 `VirtualTrackList` 的 `parent` 模式，但 `parent` 模式现在监听的是 `.detail-scroll-host`：

- 可视高度取 `scrollHost.clientHeight`，不再错误使用列表总高度
- 列表相对滚动宿主的偏移仅在初始化和 resize 时测量
- 滚动帧内只消费 `scrollTop`，不再逐帧读取 `offsetTop`

这三点是解决长歌单详情页滚动卡顿的关键。

## 四、高度变化机制

### 4.1 原理

头部高度通过 CSS calc 由 `--sticky-progress` 直接计算得出，**无 height transition**。所有依赖 `--sticky-progress` 的属性在同一帧同时变化，消除 temporal mismatch：

```css
height: calc(var(--header-full-height, 380px) - var(--sticky-progress, 0) * (var(--header-full-height, 380px) - var(--collapsed-height)));
```

`transition` 仅保留纯视觉效果：

```css
transition:
  border-radius 0.3s cubic-bezier(0.33, 0, 0.1, 1),
  box-shadow 0.3s cubic-bezier(0.33, 0, 0.1, 1);
```

### 4.2 Scroll anchoring 防护

所有滚动容器（`.detail-scroll-host`）上设置：

```css
overflow-anchor: none;
```

防止头部高度变化触发 scrollTop 反馈振荡。

### 4.3 高度变体

| 页面类型 | 吸顶态高度 | 说明 |
|---|---|---|
| 无 tabs 的详情页 | `80px` | 仅 mini 行 |
| 有 tabs 的详情页（歌手/歌单/专辑/播客） | `134px` | mini 行 + 紧凑 tabs 行 |

有 tabs 时 header 自动获得 `has-header-tabs` class，`--collapsed-height` 从 80px 切换为 134px。

### 4.4 Header 高度重测

数据就绪后 `watch(ready)` → `nextTick(remeasureHeight)` 重新测量包含 tabs 的 header 全高，`--header-full-height` 自动更新（fallback 380px）。

## 六、背景模糊架构

### 6.1 唯一 blur 来源

仅 `App.vue` 的 `.content::before` 提供模糊背景，所有详情页不再各自渲染 `::before`：

```
App.vue — .content::before
  └── 唯一 blur（360px 高，scale(1.1) 模糊，深色渐变遮罩）
  └── 封面图来自 --cover-bg-url，由 useDetailStickyState 自动同步

详情页（所有）
  └── 无 ::before
  └── 无 background（透明，透出 content blur）
  └── 通过 composable 将封面 URL 同步到 .content
     └── onBeforeUnmount 自动清理
```

### 6.2 封面 URL 同步

`useDetailStickyState` 统一接管 `--cover-bg-url` 同步，各页面不再自行实现 watcher：

```typescript
// 在 composable 内部
if (coverUrl) {
  watch(coverUrl, (url) => {
    const el = document.querySelector('.content') as HTMLElement | null;
    if (!el) return;
    if (url?.trim()) {
      el.style.setProperty('--cover-bg-url', `url("${url.trim()}")`);
    } else {
      el.style.removeProperty('--cover-bg-url');
    }
  }, { immediate: true });
}

// onBeforeUnmount 时自动清理
contentEl?.style.removeProperty('--cover-bg-url');
```

### 6.3 `--blur-opacity` 同步

当 scroll host 不是 `.content` 自身时（即独立滚动容器场景），每帧同步 `--blur-opacity`，使 blur 随滚动淡出：

```typescript
function syncBlurOpacity(progress: number): void {
  const contentEl = document.querySelector('.content');
  if (contentEl) {
    const blurOpacity = Math.max(0, 1 - progress * 1.5);
    contentEl.style.setProperty('--blur-opacity', String(blurOpacity));
  }
}
```

## 七、统一状态管理：useDetailStickyState.ts

### 7.1 API

```typescript
type UseDetailStickyStateOptions = {
  embedded?: boolean;
  rootRef?: Ref<HTMLElement | ComponentPublicInstance | null>;
  scrollHostRef?: Ref<HTMLElement | null>;
};

export function useDetailStickyState(
  coverUrl?: ComputedRef<string>,          // 可选，封面 URL，自动同步 blur 背景
  options: boolean | UseDetailStickyStateOptions = false,
): { refresh: () => void }
```

- `boolean` 写法仍可用：`true` 等价于 `{ embedded: true }`
- 推荐传入 `rootRef` / `scrollHostRef`，避免 `KeepAlive`、分屏详情、多详情页并存时通过全局选择器串绑到错误节点
- scroll host 固定为页面内部的 `.detail-scroll-host`；嵌入模式下 `.detail-panel` 只负责承载背景、圆角和边框，不再承担滚动
- **自动生命周期管理**：mount 时绑定 scroll 事件，unmount 时清理 `--sticky-progress`、`--blur-opacity`、`is-sticky-header` class、`--cover-bg-url`

### 7.2 典型用法

```typescript
// 独立模式
const { refresh } = useDetailStickyState(
  computed(() => playlist.value?.coverImgUrl?.trim() || ''),
);

// 嵌入模式
const { refresh } = useDetailStickyState(
  computed(() => playlist.value?.coverImgUrl?.trim() || ''),
  {
    embedded: !!props.embedded,
    rootRef: detailPageRef,
    scrollHostRef: detailScrollHostRef,
  },
);
```

### 7.3 关键常量

| 场景 | PROGRESS_DISTANCE | scroll host |
|---|---|---|
| 独立模式 | 324px | `.detail-scroll-host` |
| 嵌入模式 | 120px | `.detail-scroll-host` |

### 7.4 已接入的详情页


- `.detail-panel` → 只负责边框、圆角、背景和左右/底部内边距；顶部 padding 必须为 `0`
- `.detail-body-wrap` → 提供 `height: 100%` 的 flex 包裹层，嵌入详情页可在其中自然铺满
- `.detail-scroll-host` → 唯一滚动容器，同时作为 `ScrollToTopFab` 的监听目标

### 9.2 嵌入高度链

```
.detail-panel (padding-top: 0; padding-inline: 18px; padding-bottom: 18px)
  └─ .detail-body-wrap (height: 100%; display: flex)
       └─ .playlist-detail-page--embedded (height: 100%)
            ├─ DetailStickyHeroHeader
            └─ .detail-scroll-host (overflow-y: auto)
```

该结构的关键约束是：**不要在 `.detail-panel` 顶部保留 padding，再让子节点用负 margin 抵消。**  
因为 sticky header 的定位基准会受到父容器顶部 padding 影响，哪怕内容整体被上提，header 仍会被卡在 padding 下面，形成“用户页右侧顶部空白”。

### 9.3 数据流

UserPanel 通过 `:embedded="true"` 传递给内嵌的详情页（PlaylistDetailPage / AlbumDetailPage / PodcastDetailPage），composable 据此缩小 PROGRESS_DISTANCE，并监听各页面内部的 `.detail-scroll-host`。

### 9.4 嵌入模式下的虚拟滚动与无限加载

PlaylistDetailPage 使用虚拟滚动渲染歌曲列表，通过监听滚动容器的 `scroll` 事件计算 `songListScrollTop`，确定当前可视区应渲染的歌曲范围。嵌入模式下需同步调整以下机制：

#### 9.4.1 虚拟滚动滚动宿主

所有详情页统一使用 `VirtualTrackList` 的 `parent` 模式，滚动宿主始终为 `.detail-scroll-host`：

```typescript
const scrollHostSelector = () => detailScrollHostRef.value;
```

#### 9.4.2 IntersectionObserver root

无限滚动（`loadMoreSongs`）通过 `IntersectionObserver` 监听 sentinel 元素触发，`root` 也应对齐到 `.detail-scroll-host`：

```typescript
scrollObserver = new IntersectionObserver(callback, {
  root: detailScrollHostRef.value,
  rootMargin: '400px',
});
```

#### 9.4.3 `currentToken` 作用域

`fetchDetail` 和 `loadMoreSongs` 使用 `currentToken` 防止并发请求的响应污染。原代码将 `currentToken` 声明为 `fetchDetail` 内的局部 `const`，`loadMoreSongs` 引用时实为 `undefined`，导致 `undefined !== fetchToken` 恒为 `true`，`loadMoreSongs` 始终 return。修复为模块级变量：

```typescript
let fetchToken = 0;
let currentToken = 0;  // 模块级，两个函数都可访问

async function fetchDetail(id: number) {
  currentToken = ++fetchToken;  // 赋值而非 const 声明
  // ...
}
```

#### 9.4.4 初始歌曲加载上限

`getPlaylistDetail(id, s, cookie)` 的 `s` 参数为初始返回歌曲数上限，原为 `s=100`。对于超过 100 首歌的歌单需靠无限滚动加载剩余歌曲。批量加载至 `s=1000`，减少对无限滚动的依赖：

```typescript
const { data } = await getPlaylistDetail(id, 1000, userStore.loginCookie || undefined);
```

## 十、Temporal Dead Zone 防范

`useDetailStickyState` 内部立即执行 `watch(coverUrl, ..., { immediate: true })`，在 setup 阶段就会访问 `coverUrl.value`。因此 **coverUrl 依赖的所有变量必须定义在 composable 调用之前**。

错误示例（PodcastDetailPage 曾遇到的问题）：

```typescript
// ❌ hero 在 useDetailStickyState 之后定义
const { refresh } = useDetailStickyState(computed(() => hero.value.coverUrl?.trim() || ''));
const hero = computed(() => ...);
```

正确顺序：

```typescript
// ✓ hero 在 useDetailStickyState 之前定义
const hero = computed(() => ...);
const { refresh } = useDetailStickyState(computed(() => hero.value.coverUrl?.trim() || ''));
```

### 13.1 新增详情页

1. 直接使用 `DetailStickyHeroHeader.vue`，无需自行实现吸顶
2. 模板根容器使用 `class-name="playlist-detail-page"`，获得共享滚动容器样式

4. 如果页面有返回按钮，使用 `class="playlist-detail-back"`（公共样式已处理过渡）
5. **如果页面有 Tab 栏**：将 tabs 放入 `<template #tabs>` slot，tabs 自动嵌入 header 底部吸顶
6. 如果页面会嵌入 UserSplitView，模板加 `:class="[embedded && 'playlist-detail-page--embedded']"`，composable 传 `{ embedded: true, rootRef, scrollHostRef }`

### 13.5 常见问题排查

#### 13.5.1 嵌入模式头部不吸顶 / 头部滑走

**现象**：嵌入 UserSplitView 后，吸顶头部不固定，随内容一起滚动滑走。

**根因**：`position: sticky` 的粘性受限于包含块（父容器）高度。当父容器 `.playlist-detail-page--embedded` 的实际高度不足时，粘性元素会随父容器一起离开视口。

**检查清单**：
1. 页面根元素是否加了 `:class="[embedded && 'playlist-detail-page--embedded']"`？
2. `useDetailStickyState` 是否传了 `{ embedded: true, rootRef, scrollHostRef }`？缺少 ref 时，在多详情页并存或缓存恢复场景下可能监听到错误节点
3. `DetailStickyHeroHeader` 是否传了 `:embedded="embedded"`？缺少会导致 header 的宽度铺满失效

| 详情页 | 曾遇到的问题 | 修复 |
|---|---|---|
| `PodcastDetailPage.vue` | 根元素缺少 `--embedded` class | 添加 `:class="[embedded && 'playlist-detail-page--embedded', 'podcast-detail-page']"` |
| 用户页右侧 5 类详情 | `.detail-panel` 顶部保留 18px padding，sticky header 被卡在 padding 下方 | 改为 `padding: 0 18px 18px`，彻底移除“负 margin 补偿顶部空白”方案 |

#### 13.5.2 切换数据后头部状态残留

**现象**：切换 Tab/条目后，吸顶头部保持折叠态或滚动位置异常。

**根因**：详情页数据更新时未重置 scrollTop 和 `--sticky-progress`。

**修复要求**：数据切换时需调用 `refresh()`（设置 `scrollHost.scrollTop = 0` 并强制更新 progress）：

```typescript
// 独立页面 Tab 切换
watch(activeTab, () => { refresh(); });

// 嵌入模式条目切换（watch 数据 ref）
watch(() => album.value?.id, () => { requestAnimationFrame(() => refresh()); });
// 或 watch props
watch(() => props.detail, () => { requestAnimationFrame(() => refresh()); });
```

| 页面 | 触发条件 | 修复方式 |
|---|---|---|
| `UserDetailPage.vue` | 切换创建/收藏歌单 tab | `watch(activeTab, refresh)` |
| `AlbumDetailPage.vue` | 嵌入模式切换不同专辑 | `watch(() => album.value?.id, rAF(refresh))` |
| `PlaylistDetailPage.vue` | 已修复：watch playlistId 内含 `rAF(refresh)` |
| `PodcastDetailPage.vue` | 已修复：watch detail 内含 `rAF(refresh)` |

#### 13.5.3 嵌入模式头部左右两侧宽度未填充面板

**现象**：嵌入 UserSplitView 后，吸顶头部在置顶态时左右两侧没有扩展填满 `.detail-panel` 的 `padding: 18px` 区域，与面板边缘留有间隙。

**根因**：`DetailStickyHeroHeader.vue` 对 `.playlist-detail-header-wrap` 施加 `margin-left/right: calc(var(--space-4) * -1)`，而 `.playlist-detail-page`（`detail-page.css`）也施加相同的负 margin，两层叠加导致 header 左移 -32px 而非预期的 -16px。

**已修复**：`detail-page.css` 中增加全局规则，覆盖所有使用 `.playlist-detail-page` + `DetailStickyHeroHeader` 的页面：

```css
/* detail-page.css — 全局规则，所有详情页共享 */
.playlist-detail-page:not(.playlist-detail-page--embedded) .playlist-detail-header-wrap {
  margin-left: 0 !important;
  margin-right: 0 !important;
}
```

- **独立模式**：`.playlist-detail-page` 无 `--embedded` class → `:not()` 匹配 → `!important` 生效，取消 header wrap 自身的负 margin，仅保留 `.playlist-detail-page` 的负 margin（-16px） ✅
- **嵌入模式**：`.playlist-detail-page.playlist-detail-page--embedded` → `:not()` 不匹配 → 规则不应用 → `.detail-sticky-header--embedded` 的负 margin 正常工作  ✅

**提醒**：此规则已在 `detail-page.css` 中全局生效，新增详情页无需自行处理 header margin 复位。
