# 关闭按钮与系统托盘行为修复实现总结

> 对应问题：点击主界面关闭按钮（×）后，窗口消失但托盘残留，且无法从托盘重新打开主界面。
> 实现时间：2026-07-04
> 涉及文件：`electron/main.js`、`electron/preload.js`、`src/components/TopBar.vue`、`src/components/SettingsPage.vue`

---

## 一、问题根因

### 1.1 核心发现：Electron 42 中 window.close() 不触发 BrowserWindow.on("close") 事件

在 Electron 42 + `frame: false`（无边框窗口）的 Windows 环境下，渲染进程调用 `window.close()` 会直接关闭 Chromium 底层窗口，**不会触发** `BrowserWindow.on("close")` 事件。因此此前注册的 close handler（`event.preventDefault()` + `win.hide()`）**从未被执行**。

日志证据：三次启动均有 `[createMainWindow] registering close handler`，但三次点击关闭按钮均无 `[close]` 日志，取而代之的是 `[lifecycle] window-all-closed` → `[lifecycle] before-quit`。

### 1.2 旧代码的 app.isQuitting() 不存在

旧代码使用 `app.isQuitting()`，此 API 在 Electron 42 中不存在，返回 `undefined`，`!undefined` 始终为 `true`，导致 close handler 始终拦截所有关闭事件，托盘"退出"菜单也无法正常退出。

---

## 二、解决方案

### 2.1 核心思路：改走 IPC 路径

不再依赖 `win.on("close")` 事件拦截，而是让 TopBar 的关闭按钮发送 IPC 消息给主进程，由主进程的 `window-close` IPC handler 决定隐藏还是退出。

### 2.2 流转路径

```
用户点击 ×
  ↓
TopBar.vue → window.appEnv.closeWindow()
  ↓
ipcRenderer.invoke("window-close")   ← IPC 消息
  ↓
main.js window-close IPC handler
  ├─ isQuitting=false, mode="hide" → bw.hide()   ← 隐藏到托盘
  └─ otherwise → destroy + app.quit()            ← 完全退出
```

---

## 三、改动清单

### 3.1 electron/preload.js — 新增窗口控制 IPC bridge

在 `contextBridge.exposeInMainWorld("appEnv", {...})` 中新增：

- `closeWindow: () => ipcRenderer.invoke("window-close")`
- `minimizeWindow: () => ipcRenderer.invoke("window-minimize")`
- `maximizeWindow: () => ipcRenderer.invoke("window-maximize")`
- `isWindowMaximized: () => ipcRenderer.invoke("window-is-maximized")`
- `closeBehavior` 配置读写 API

### 3.2 src/components/TopBar.vue — 关闭按钮改用 IPC

```js
// 改前
function closeWindow() { window.close(); }

// 改后
function closeWindow() { window.appEnv.closeWindow(); }
```

这是最关键的一行改动——将关闭路径从 `window.close()`（不走 close 事件）改为 IPC（走 `window-close` handler）。

### 3.3 electron/main.js — window-close IPC handler 实现完整逻辑

```js
ipcMain.handle("window-close", (event) => {
  const bw = BrowserWindow.fromWebContents(event.sender);
  if (!bw || bw.isDestroyed()) return;

  if (!isQuitting && closeBehaviorConfig.mode === "hide") {
    bw.hide();           // 隐藏到托盘
  } else {
    isQuitting = true;   // 完全退出
    bw.destroy();
    if (mainTray) { try { mainTray.destroy(); } catch {} mainTray = null; }
    if (lyricTray) { try { lyricTray.destroy(); } catch {} lyricTray = null; }
    app.quit();
  }
});
```

### 3.4 electron/main.js — closeBehavior 配置系统

新增配置持久化（JSON 文件 `close-behavior.json`）：

- `let isQuitting = false` — 全局退出标记
- `let closeBehaviorConfig = { mode: "hide" }` — 配置对象
- `loadCloseBehaviorConfig()` — 启动时加载
- `setCloseBehaviorConfig(config)` — 写入配置 + 广播变更
- `getCloseBehaviorConfig()` — 读取配置

### 3.5 src/components/SettingsPage.vue — 设置开关

在外观 tab 新增开关项「关闭主窗口时隐藏到托盘」。

数据流：

```
拨动开关 → watch → setConfig({ mode: "hide"|"quit" })
  → 主进程写 JSON 文件 + 广播 config-changed
  → 下次关闭按钮按新配置执行
```

### 3.6 electron/main.js — 生命周期日志（调试用）

在 `window-all-closed`、`before-quit`、`window-close` IPC handler 中追加 `writeMainLog`，用于追踪关闭流程。

## 六、架构说明

### 关闭路径对比

| | 旧方案（已废弃） | 新方案 |
|--|-----------------|--------|
| 触发方式 | window.close() → BrowserWindow.close() | IPC window-close |
| 事件依赖 | win.on("close") | ipcMain.handle("window-close") |
| 拦截机制 | event.preventDefault() | bw.hide() 不回传 close 事件 |
| 退出路径 | close handler 放过 → window-all-closed → app.quit() | isQuitting=true → bw.destroy() → app.quit() |
| 配置支持 | 无 | closeBehaviorConfig.mode |

### 为什么保留了 win.on("close") handler

close handler 仍保留在 main.js 中，作为 macOS 的兜底（macOS 上 window.close() 仍会触发 close 事件）。但在 Windows + frame: false 环境下不会被执行。
